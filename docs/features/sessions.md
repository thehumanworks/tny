# Sessions

Applies to the **native** backend fully. Host backends store their own threads; tny keeps a thin local alias so `tny resume last` still works.

## Identity

Session ids are generated by tny, opaque, unique per workspace. List is workspace-scoped by default (`--all` for every workspace). Pagination: `--limit 1-100`, `--cursor`.

## On disk

```text
~/.tny/sessions/<workspace-hash>/<id>/
  session.json      # metadata, messages, tool steps (redacted)
  results/          # large tool-result blobs, referenced by handle
  recovery.json     # partial assistant text + last event offset
```

`session.json` never stores API keys or MCP header values. Tool results larger than `max_tool_result_bytes` live in `results/` with a handle the model reads via `read_tool_result`.

## Resume

```bash
tny -r
tny resume last
tny resume <id>
tny ask --resume last "continue"
```

Host mapping:

| Backend | Stored pointer |
| --- | --- |
| cursor | `agent_id`, `run_id`, workspace, model |
| codex | `thread_id` |
| acp | agent argv + `sessionId` |
| openai | full transcript |

## Compaction (native)

After **eight** completed turns, keep the latest **four** verbatim and replace older turns with a structured summary (requests, outcomes, files, commands, interruptions). `/compact` forces condensation of everything before the latest turn. The on-disk transcript stays intact; only the model view shrinks. Host backends: send `/compact` only if the protocol has an equivalent; otherwise no-op with a status line.

## Recovery

Persist streaming text and tool progress continuously. `/continue` and `tny ask --resume last --continue-recovery` replay from `recovery.json`. `tny session recover <id>` copies a corrupt session. `tny doctor` prints the recover command when it can fix a file.

## Isolation

Additional directories do not create sessions or history. Primary workspace owns the session key.

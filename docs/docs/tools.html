Tools, MCP, skills

The native loop owns tools. Host backends own theirs.

Built-in tools

Native loop only, unless noted. Names match fx where muscle memory transfers.

Large results are a bounded preview plus a session handle. memory writes ~/.tny/memories.json only when asked.

MCP

Trusted profile only: ~/.tny/mcp.json. Repo-local MCP files are never loaded — cloning a repo must not start a server. Treat server output as untrusted data.

{
  "servers": {
    "local": { "command": ["node", "server.js"] },
    "remote": {
      "type": "http",
      "url": "https://mcp.example/mcp",
      "bearer_token_env": "EXAMPLE_MCP_TOKEN"
    }
  }
}

Existing stdio JSONL entries keep their shape. Remote entries use Streamable HTTP: one POST per JSON-RPC message, answered by one JSON document over fixed-length or arbitrarily split chunked framing. Legacy Mcp-Session-Id and stateless MCP 2026-07-28 are supported. Authentication comes from environment-backed headers and is never logged.

SSE is intentionally unsupported: tny does not parse text/event-stream, open a GET event stream, or fall back to legacy HTTP+SSE, and returns an actionable error for an SSE-only endpoint. Wasm is remote-only: HTTP works lazily through fetch subject to CORS; stdio fails cleanly. tny acp uses only client-supplied mcpServers, not the user profile.

Skills

A directory plus SKILL.md (YAML frontmatter name, description). Metadata is discovered at startup; the body loads only on invoke.

Search order, workspace upward, stop before $HOME: skills/, .agents/skills/, .claude/skills/, .codex/skills/, .cursor/skills/, .opencode/skills/. Then ~/.tny/skills/ and the same hidden names under $HOME.

Subagents

Child native sessions. The parent does not dump the child transcript into its own context. Children cannot raise permission mode above the creator. Host backends do not get tny-spawned subagents. The child runs the parent's resolved provider — the parent forwards it on the child command line, so a remembered last_provider cannot re-route it — and a child that fails to start reports its stderr in the tool result.

Project instructions

Load AGENTS.md (and CLAUDE.md if AGENTS.md is absent) from ~/.tny/, launch ancestors, and the primary workspace. Extra dirs do not contribute instructions. context: false disables this. Over --ssh, ~/.tny/ still loads as local user policy and project instructions come from the remote cwd — not the launch directory.

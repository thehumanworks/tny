# Native MSYS private filesystem seam — design v2

This is a proposed internal OS seam, with actual disposable Windows probes. No product, CI, mount, privilege, package, or global setting changes were made. Primary allocates the next Windows ADR/contract amendment only after final independent design approval (expected ADR0105/A27; ADR0104/A26 now belongs to runner quiescence). No Windows ID is reserved by this document. Guest is Windows11 ARM64 with x64 MSYS2 emulation, not the required native x64 hosted CI.

## Observed problem and scope

Default MSYS2 noacl creates open0600 files as0644 and mkdtemp directories as0755, with inherited Users READ and Authenticated Users READ+WRITE Windows DACL grants. fchmod0600 returns success without removing those grants (../windows-ci-correction/probe.log). Separately, default symlink() deep-copies existing targets and cannot create dangling links; this explains three hosted fixture failures but does not itself show an alias guard bypass.

A new probe found an additional relevant OS seam issue: after opening a directory fd, renaming it and placing another directory at its original pathname, MSYS openat(fd,"posix-created") writes into the replacement pathname. fstatat uses the same stale path. NtCreateFile with RootDirectory equal to the retained fd's native HANDLE writes into the actual retained directory. Therefore a create-only helper followed by current MSYS fstatat/linkat/renameat/unlinkat would not preserve the export contract. The scoped native transaction must retain handles through observation, publication and cleanup.

## Proposed internal owner

Add src/util/private_fs.{c,h}, internal only, no include/ public ABI. Hide Windows types and lazy-loaded system DLL functions in its implementation. Use GetModuleHandle/GetProcAddress for ntdll and securely load system advapi32 APIs only when first needed; resolve required functions before side effects and fail closed if unavailable. No new linked dependency, C++, or process-global mount changes. POSIX branches retain existing syscalls; WASM retains its present per-instance filesystem behavior and existing unsupported native execution/publication responses.

Use one implementation of private create/open, private mkdir, secure temporary name generation, identity-checked fd admission, and an opaque staged-publication context. Avoid globally replacing unrelated util.c filesystem behavior. Input parents may be ordinary user/workspace directories; every newly created private container/file receives its restrictive ACL at creation. On Windows, existing entries reused in a private role must meet the exact owner/type/link/ACL/control policy below; foreign, nonprivate or uncertain entries fail without mutation and with a diagnostic identifying the private role and required recovery. There is no automatic repair or migration. Ordinary ancestors are traversal inputs, not implicitly private containers. This new Windows predicate does not alter existing POSIX creation/reuse/owned-mode repair behavior, explicit public-input reads, or public output overwrite policy.

## Atomic file and directory creation

1. Acquire the intended parent once. For retained-parent callers, borrow its native HANDLE through MSYS get_osfhandle; never reconstruct that parent pathname for an authoritative mutation. Check directory type. Keep original fd/handle alive through the transaction.
2. Encode a single leaf without resolving filesystem names. Refuse empty, dot/dotdot, slash/backslash, overlong and undecodable components before any side effect. Convert using the current MSYS locale and map ASCII controls1–31 plus quote/star/colon/less-than/greater-than/question/pipe to U+F0xx, matching runtime da84778c strfuncs.cc. This prevents colon becoming an NTFS alternate stream. Never use POSIX_TO_WIN cygwin_conv_path on the leaf: the actual implementation follows final symlinks. No absolute/UNC/NT namespace leaf can pass.
3. Query current TokenUser without exposing identity. Build an absolute SECURITY_DESCRIPTOR with owner=current user, DACL present and protected. New files grant that SID FILE_GENERIC_READ|FILE_GENERIC_WRITE|DELETE|WRITE_DAC|WRITE_OWNER, not FILE_EXECUTE. New directories grant owner full directory list/traverse/create/delete/control, with owner-only object/container inheritance so converter-created intermediate children remain inaccessible to other ordinary users. Directly created private files still receive their explicit non-executable file ACL. System/admin recovery privileges have their ordinary OS meaning; do not add broad Users/AuthenticatedUsers/Everyone grants.
4. Call dynamically resolved NtCreateFile with RootDirectory, leaf UNICODE_STRING, supplied descriptor, FILE_CREATE for exclusive creation, FILE_OPEN_REPARSE_POINT and OBJ_DONT_REPARSE, synchronous I/O, and FILE_NON_DIRECTORY_FILE or FILE_DIRECTORY_FILE. Do not use overwrite/supersede. Share read/write/delete to preserve POSIX replacement semantics. Required access follows the caller's operation, with READ_CONTROL for verification and DELETE for owned cleanup.
5. Immediately query the returned object's security/type by HANDLE. If ACL or identity is uncertain, delete only the newly created object by that retained handle and close it. No contents, provider request, or converter work precedes successful verification. Supplying the descriptor in NtCreateFile, rather than repairing later, is what removes the creation interval with inherited broad grants; the independent AccessCheck probe observes denial immediately before writing.
6. Native creation failure maps to errno/actionable existing error paths. FAT/non-ACL storage or unavailable native operations fail before content and are not represented as private success. Do not silently change platform support claims.

Random temporary names use existing cryptographic random source with bounded exclusive-create retries. Preserve the current existing-target refusal and no-replace semantics. No delete-by-name cleanup after a failed identity check.

## POSIX descriptor admission

Normal cygwin_attach_handle_to_fd success was probed: exact native handle transferred, read/write/lseek/fsync/fstat worked, explicit FD_CLOEXEC worked, and close(fd) closed the native handle exactly once. Runtime da84778c dtable.cc259 and fhandler/base.cc1422/1329 show no duplicate: init stores the supplied handle and close calls CloseHandle.

Do not select attach as the implementation default. Its documented API is best-effort, build_fh_name resolves the supplied pathname, and its source does not check failed find_unused_handle before indexing the descriptor table. This failure edge was found by source review, not deliberately crashed at runtime.

The safer ordinary-writer admission proved in v5 is: retain native-created handle; GetFinalPathNameByHandleW; WIN_W_TO_POSIX conversion of that already-created object's name; open existing with no CREATE/TRUNC and O_NOFOLLOW|O_CLOEXEC; compare volume/file ID of both live handles; only then expose the POSIX fd or write. A rename between lookup and open yields refusal or exact identity, never authority to write a foreign replacement. On mismatch, close the opened fd without mutation and dispose only the original newly created empty object through its retained native handle. Native stage/transaction handles remain retained separately until publication, independent of the POSIX descriptor close; publication changes the ownership state before any later fallible operation. Use the same checks for directory-fd and existing-lock admission. Final implementation must test allocation/open/fd-limit failures and duplicate-close cleanup.

## Native staged publication and retained-parent operations

Expose internal native-aware observation and staged-commit operations rather than leaking HANDLEs into core code. Source stage and parent handles remain owned until commit/cleanup, with explicit created-versus-existing and staged-versus-committed state as specified below. Query existing leaf with NtCreateFile(FILE_OPEN, relative parent, no reparse traversal), obtain type/link-count/file ID, and compare against the original observed target. Native reparse points, MSYS system-cookie symlinks, and read-only .lnk shortcuts including implicit suffix lookup must be refused as specified below. Unknown alias forms never acquire regular-file authority.

For no-replace, NtSetInformationFile(FileLinkInformation, ReplaceIfExists=false, RootDirectory=retained parent) atomically installs the source stage handle under the final leaf. EEXIST preserves the competitor. The successful link is the commit point; removing the original stage link is separate handle-based FileDispositionInformation cleanup. A failed cleanup cannot erase committed success.

For overwrite, use FileRenameInformationEx with REPLACE_IF_EXISTS|POSIX_SEMANTICS, source=retained stage handle and destination=retained parent plus encoded leaf. Classic rename was experimentally insufficient with an open old-target handle; the Ex form preserves that handle's old bytes while new opens see the replacement. Never fall back to pathname rename or delete-then-create. Unavailable Ex support must refuse cleanly without replacing anything. Observe/revalidate target identity and retain current distinct committed-result/error reporting.

Use handle-based disposition for owned stage/temporary cleanup and native directory-relative traversal for the scoped export staging cleanup; current MSYS unlinkat cannot be trusted after parent renames. Keep existing bounded directory enumeration and reparse refusal. This is part of preserving the original contract, not a new feature.

## Probes and implementation gates

Final private_create_probe.c compiled with gcc -Wall -Wextra and system advapi32 for this diagnostic only. Product must use the lazy loading described above. All checks in probe-v5.log pass. The probe shows native creation after parent rename, exact exclusive existing/symlink refusal, harmless old bytes unchanged, file/dir ACL shape, independent restricted-token AccessCheck (default broad file ALLOW versus newly created file/directory DENY before content), private inheritance to converter-like child, attach success/ownership/close, exact POSIX reopen, native atomic no-replace link and handle cleanup, and Ex overwrite while an old fd retains old bytes.

Six filename cases round-trip through actual MSYS lstat at the retained directory's current name: Unicode snowman, colon, quote/star/question, newline, trailing dot+space, CON. These are not proof for every locale/invalid-byte path; implementation tests must cover selected C/UTF8 locales, non-BMP Unicode, rejected invalid encodings and reserved private-use aliases before side effects. No conversion may resolve a final alias.

Initial header/layout compile failures and classic-rename runtime failure are preserved. Probe-v2 and later explicitly record POSIX openat writing to the replacement parent; these results are findings, not passed POSIX retained-parent guarantees. The disposable probes are not product tests or native x64 CI.

After the allocated Windows ADR/amendment and final independent design approval: implement/freeze the host primitive first for independent source review, then route the listed callers. Add independent native ACL test helpers (AccessCheck/restricted token, not only the implementation predicate), prewrite paused boundaries, failure cleanup/exhaustion, parent replacement, real symlink/hardlink aliases, first-writer wins and old-target bytes. ## V2 normative API and ownership details

These clauses complete and constrain the preceding architecture. V1 remains byte-for-byte preserved as DESIGN.md. The API names below are internal proposed names, not additions to the libtny public ABI.

### Acquired directory and file objects

`tny_private_dir` owns a directory descriptor and, on MSYS, a retained native handle/identity. It carries an optional cached pathname solely for diagnostics/argv. `tny_private_file` owns a retained native object handle plus optional identity-checked POSIX I/O fd, desired access, original parent/leaf, and an ownership state. The object never infers deletion authority merely from a pathname or a successful read-only reopen.

Internal operations are `dir_acquire_namespace_anchor`, `dir_open_beneath`, `dir_create_at`, `file_create_at`, `file_open_existing_at`, `file_dup_io_fd`, `file_observe_at`, `file_publish`, `file_keep_entry`, and `file_release`. Ordinary path-taking wrappers acquire the parent once and then use these objects. Bounded random-temp wrappers return an owned file object, not a bare fd and name. Creation and publication helpers are responsible for disposing their own unpublished object after short write/fsync/open failures; callers retain ordinary existing-error/result behavior. A failed reopen of an existing lock or public input only closes handles, never deletes or changes that object. Durable item logs explicitly keep their accepted entry after successful creation/verification so later log failures retain existing partial-log behavior. Publication staging objects remain unpublished until the actual commit operation succeeds.

### Confined reads (A20)

Route `image_io.c:open_beneath` and `tny_image_io_read_confined` through native relative opens on MSYS, not just private writes. Capture the trusted MSYS mount namespace used for root acquisition, preserving longest component-boundary mount matching. Drive mappings such as `/c` are namespace anchors, not physical children of the MSYS installation root. Acquire the trusted native volume/mount anchor, then open each remaining real filesystem component relative to the retained previous handle with FILE_OPEN, no reparse traversal, expected directory type, and alias classification. Do not convert or realpath the full untrusted root; that could follow and erase ancestor aliases before checks. Mount-boundary handling is explicit, bounded and fails closed on uncertain/unsupported mapping.

Each opened component becomes the next authority even if its former pathname is renamed/replaced. Final file acquisition checks ordinary bounded-file type and admits a read-only POSIX fd only after native identity equality. No private ACL requirement applies to explicit public input files or general confined source bytes; confinement and private-file reuse are distinct policies. Existing explicit `read_input` semantics remain unchanged. Read failures leave the output empty. Tests must acquire the root or intermediate ancestor, rename/replace it, and demonstrate that reads use the acquired object or safely fail; they must never read replacement-tree bytes. Include `/tmp`, drive/mount roots such as `/c`, prefix lookalikes, mount boundaries, sys/native/lnk aliases and every intermediate component.

### Transform stage context

Replace `char *tny_image_stage_dir(...)` with an opaque `tny_image_stage *tny_image_stage_create(...)` in private image_transform.h. The context retains the directory acquired at creation until destruction, on POSIX as a dirfd and on MSYS with native directory identity/handle. `stage_write(stage, leaf, ...)`, `stage_read(stage, leaf, ...)`, `stage_path(stage, leaf)` and `stage_destroy(stage)` take that context. `stage_path` returns a generated argv view, never cleanup/readback authority; `stage_directory_path(stage)` similarly supplies HOME/TMPDIR to the converter. The context—not a later opendir(path)—owns all cleanup.

Change `tny_image_tool_run`'s internal private-stage argument to a const stage context (NULL remains valid for the version probe). It derives the sanitized HOME/TMPDIR and generated path views and retains the context throughout each converter/decode call. Check the displayed stage name against retained identity before exposing it to a pathname-consuming child; never substitute a newly acquired replacement context. Windows stage handle sharing must pin the created stage during child pathname use, and ancestor/leaf rename tests must establish that this pin or safe refusal works; no pathname precheck alone is a race-free claim. Readback and cleanup always use the retained original directory regardless of converter/path failure. If a stable pathname view cannot be established, fail before spawning the converter. The stage stays owned until the child is quiescent under the existing process contract.

`core/image_export.c:export_operation.stage` becomes the opaque pointer. Its dispose routine calls one stage destructor and does not separately free the old string. Update stage_inputs, cell/contact-sheet argv builders, decode validation, producing conversion, readback and all error exits. POSIX also retains a dirfd while preserving current mode, generation and public-input behavior. WASM stage creation/tool execution continues to fail without opening or mutating anything.

The destructor enumerates only through the retained directory. On MSYS use native handle-relative opens/queries/disposition for each bounded generated child; reject aliases/subdirectories/unexpected forms rather than following them. Remove only entries whose identities were acquired beneath that directory. Dispose the original directory through its owned handle; a replacement directory at the old display path is never enumerated or removed. If cleanup cannot be proved, report the existing cleanup/failure outcome without touching foreign objects.

### Windows private-role reuse policy

Apply the new predicate only to Windows new-feature private roles: jobs root, each job directory, reservations directory, their state/owner/claim locks, job records/snapshots/item logs; image-guards directory and guard locks; explicitly private manifest/output/staging files newly owned by this operation. Ordinary HOME/workspace and pre-existing legacy `.tny` ancestors do not become private roles by traversal. Public inputs and an explicitly selected existing overwrite destination do not need a private ACL. New intermediate directories created by a private mkdir wrapper receive the new restrictive ACL; existing ordinary ancestors are type/alias checked but are not repaired or required to be owner-private.

For a reused private-role object require current-user owner, expected file/directory type, no recognized or uncertain alias, and, for lock/regular private files, one hard link. Require a present protected DACL of understood ordinary ACE forms, whose access-allow principals are only the current user. Reject broad grants even if READ_DATA is absent: WRITE_DATA/APPEND, DELETE, WRITE_DAC, WRITE_OWNER, directory ADD_FILE/ADD_SUBDIRECTORY/DELETE_CHILD, and unsupported/object/callback ACE forms must not acquire authority. The conservative owner-only rule also rejects broad System/Admin allow entries instead of attempting privilege-policy inference; OS administrative recovery privileges remain outside this data-access guarantee. Null/missing ACL, unknown owner, query errors and malformed ACLs fail closed. Inherited owner-only converter-created children may be read only inside their still-owned protected stage after type/identity/ACL validation; this does not authorize reusing such an unprotected file as a lock or other private-role object.

A nonprivate/foreign/uncertain private-role entry gets an actionable refusal before any truncate, lock-owner content update, rename, cleanup or permission mutation. No automatic Windows chmod, delete/recreate or migration is authorized. Preserve current POSIX creation/reuse/owned-mode repair and public-input behavior exactly; do not move this predicate into a platform-independent filesystem helper.

### Literal names and all MSYS alias forms

Authoritative native opens use the encoded literal component only. Explicitly reject input U+F000–U+F0FF before side effects because it includes forward/reverse runtime escape collisions; user-supplied colon/control characters are encoded, not interpreted as streams or separators. Invalid locale encoding, traversal, slash/backslash, empty and overlong components fail before creation. Preserve valid Unicode/non-BMP and ordinary reserved/trailing names where MSYS round-trip can be verified.

Before accepting an existing leaf/component as ordinary, query it without following reparse points. Reject native reparse points, SYSTEM-cookie candidates, and read-only `.lnk` candidates (including uncertain shortcut formats) rather than attempting to execute/resolve them. For a literal name not found, inspect the literal `name.lnk` candidate under the same retained parent where MSYS implicit suffix resolution would apply. A read-only shortcut candidate is an alias/ambiguous destination, not an absent ordinary leaf. These checks never use a pathname-resolving conversion. Conservative ambiguous-shortcut refusal is explicit Windows behavior; ordinary explicit public-input APIs are unchanged. A newly created literal entry uses FILE_CREATE, so concurrent literal competitors cannot be overwritten; a concurrently appearing suffix alias is never followed.

Permanent tests must construct verified winsymlinks:sys, winsymlinks:lnk (including explicit and implicit suffix forms), and native existing links. Check fixture lstat/readlink before assertions; fail rather than copy/skip. Include literal `.lnk` candidates, native reparse attributes and escape-code-point collisions. Post-open identity checks are necessary but do not replace alias classification before observation/rename.

### Commit and deletion state machine

States are `EXISTING_BORROWED`, `CREATED_UNPUBLISHED`, `KEPT_ENTRY`, `LINK_COMMITTED_STAGE_PENDING`, `RENAME_COMMITTED`, and `CLOSED` with an independent cleanup-error flag. Existing borrowed objects never gain disposition authority. Only a created unpublished object may be disposed on an ordinary abort. `file_keep_entry` transfers an accepted durable log/new-file entry to persistent ownership; later release closes it without deletion.

Successful native nonreplacement link changes state to LINK_COMMITTED_STAGE_PENDING immediately, before any close/fsync/manifest work. The original stage link may then be disposed by its original handle; the published destination remains. Failure to remove that original link records a committed cleanup error and cannot reverse committed output or report an uncommitted result.

Successful RenameInformationEx changes state to RENAME_COMMITTED immediately. Its retained stage handle now names the final output: release MUST close it and MUST NOT call ordinary disposition on it. Every postcommit failure preserves the existing committed/path/producer result. File state and created-versus-existing ownership survive fd-reopen failure, close failure and all caller error exits. Tests must inject failure after each commit point and prove the output remains, only the original link is cleanup-eligible, old-target handles keep old bytes, and every owned handle is closed exactly once.

### Complete implementation acceptance matrix

- Independent Windows AccessCheck or a restricted-token open oracle covers file read/write/append plus WRITE_DAC/WRITE_OWNER/DELETE; directory list/create-file/create-subdirectory/delete-child and control rights. Default inherited broad-parent controls and deliberately broad control-only harmless fixtures must demonstrate that the oracle detects the permissions it claims. Do not call only the product ACL predicate from the test.
- Pause immediately after creation before first write/provider/converter work; verify the restricted descriptor is already present and denied. Inject descriptor allocation, native-create/query, path conversion, POSIX open, fd exhaustion, identity mismatch, short write, fsync and close failures. Confirm no foreign modification/deletion, no double close, no accepted uncertain private entry and no secret-bearing creation interval.
- Exercise acquired-root and intermediate-parent rename/replacement for confined reads, ordinary private writers, export observation/publication and stage readback/cleanup. Check stage pathname pin/safe-refusal before converter spawn and preserve unrelated sentinels. Do not leave any authoritative MSYS openat/fstatat/linkat/renameat/unlinkat path unreviewed in this six-caller scope.
- For every filename case perform actual identity-checked reopen/read/write, not just lstat: Unicode/non-BMP, C and UTF-8 locale behavior, invalid sequences, controls, colon versus alternate streams, U+F000–F0FF rejection, reserved/trailing names and drive/mount-root paths. Full leaf conversion must never resolve a final link.
- Test existing private directories/locks with foreign owner, broad data/control grants, null/malformed/unsupported ACLs, extra hard links, sys/native/lnk aliases and query errors; refusal leaves bytes, identities, ACLs and unrelated entries unchanged. Reused valid private entries remain usable. POSIX existing-mode behavior and explicit public-input reads remain positive controls.
- Test first-writer wins, overwrite with old fd retained, every post-link/post-rename failure, and native missing-function/unsupported filesystem errors. Preserve committed-artifact reporting, bounded cleanup, noninheritance/CLOEXEC, WASM clean behavior and native size gates. ARM guest probes remain feasibility evidence; source review, product fixture results and hosted native x64 Windows full unit/jobs checks remain separate mandatory gates.

No new product tests were run for this design revision. The original77-check v5 probe remains unchanged and does not claim to cover the expanded permission/failure/alias matrix above.

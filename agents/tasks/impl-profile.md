## Spec (from issue #100, ADR 0057, ADR 0064)
Add an opt-in tool profile that changes what the native OpenAI-compatible loop ADVERTISES and ACCEPTS, without deleting any implementation. Read first: docs/adr/0057-shell-first-native-loop.md (in this worktree now), docs/adr/0064-cli-verb-conventions.md, src/core/tools.c (SCHEMA_JSON ~75-190, schema_tool_disabled/hidden ~191-208, tools_schema_json ~231-258, validate_call_schema ~326-349, dispatch ~478-485), src/core/config.c/.h, src/backends/openai/openai.c (build_system_prompt ~178-226, tools array use ~277-283 and ~327-335), src/core/tools_shell.c, tests/integration/mock_openai.py and test_openai.py, docs/features/mcp-and-skills.md, docs/settings.md.
- Setting `tools` in ~/.tny/settings.json and env `TNY_TOOLS` with values `all` (default, unchanged), `terminal+edit`, `terminal`. Precedence: env > settings. `tny doctor` and `tny status` report the active profile.
- `terminal+edit` advertises terminal, edit_file, read_image (pixels cannot ride stdout, ADR 0008), and ask_user_question in interactive sessions (keep the existing interactive-only rule). `terminal` advertises terminal only (plus read_image, because pixels — state this in the ADR as the one exception and why).
- Enforcement, not just advertisement: a call to a built-in that the active profile does not advertise must fail validation with the ordinary "unknown tool <name>" error and never reach dispatch. libtny custom tools (ADR 0038) are still appended and callable in every profile. MCP meta-tools are hidden in shell profiles (the model uses `tny mcp call`), but `mcp_select_tool` stays callable from the SDK/replay paths only if that is how it works today; otherwise treat it like any unadvertised built-in — document what you chose.
- Native CLI/TUI only: `library_mode` (which disables terminal) and wasm (where terminal is the clean error, ADR 0017) ignore the profile and keep `all`; `tny acp` server mode keeps `all`. Log one status line when a profile is ignored.
- System prompt: in shell profiles, build_system_prompt appends a short, STABLE block (cache-friendly, no per-turn variation): commands start in the workspace cwd and cwd resets each call so chain with &&; inspect with `rg -n` / `sed -n`, never dump whole files; mutate with `tny edit FILE` (exact match; exit 2 = zero or many matches; never `sed -i`); read the `exit:` line before claiming success; `tny mcp call SERVER/TOOL` with JSON on stdin (the MCP catalog already in the prompt names the tools); images via `tny image attach PATH` and questions via `tny ask-user "..."` — if either prints "no session socket", skip / state the assumption (these verbs land with issue #98; word the prompt so it stays true before and after); subagents only via `tny ask -B --json ...` then `tny session ID --wait --json`, never a foreground `tny ask` inside a turn. Host backends never receive this block. In `terminal+edit` the block says to use the edit_file tool instead of `tny edit`.
- Result shape for shell profiles: the terminal tool result becomes `exit: N` / `bytes: N` / `cwd: <path>` then a preview (cap: min(max_tool_result_bytes, 8 KiB)) and, when truncated, `full: <path>` to a 0600 file holding the COMPLETE output streamed from byte zero (today tools_shell.c keeps only the first 512 KiB, SHELL_MAX_OUT, before bounding — stream to the file while reading so nothing is lost; keep a hard cap, e.g. 64 MiB, and say so). File location: `<session dir>/results/` when a session exists, else `~/.tny/results/` (the same directory `tny mcp call` uses for its spill file; reuse its naming helper if practical). In the `all` profile keep today's result shape and the read_tool_result handle unchanged so existing tests still pass.

A new mock_openai.py mode asserting the request's tool-name set is exactly the profile's set for BOTH Chat Completions and Responses wires, that an unadvertised tool call is rejected, and that the shell-profile prompt block is present only in shell profiles.
